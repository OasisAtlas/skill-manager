# 工作原理

`skill-manager` 由三层组成：

1. **默认路由层**：全局 `AGENTS.md` 将安装、添加、下载或导入 Skill 的请求先交给 `skill-manager`。
2. **决策层**：`SKILL.md` 要求先检查对象 Skill，介绍其能力与流程，并取得明确分类决定。
3. **执行与登记层**：官方 `skill-installer` 负责下载；`scripts/catalog.py` 负责分类目录与可选前缀别名。

分类目录位于 `~/.codex/skill-manager/catalog.json`，与上游 Skill 包分离。这样升级或重新安装上游 Skill 时，不会顺带覆盖分类数据。

类目前缀别名是独立的薄 Skill，只要求 Codex 转去读取正本。它不会复制正本内容，也不会改变正本的权限、依赖和更新来源。

## 关键设计决定

- **分类可选，确认必选**：未分类是合法结果，但安装前必须经过一次明确决定。
- **下载职责不重复**：本项目不重新实现 GitHub 下载、认证或 curated Skill 安装。
- **全局路由显式安装**：可靠默认入口需要用户允许修改全局 `AGENTS.md`。
- **可逆且有边界**：安装器只管理带标记的规则块；别名删除前必须验证管理标记。
